## The four evaluation criteria buckets

An evaluation harness must decouple quality into four orthogonal dimensions. Never collapse all four into a single unweighted average.

| Criteria Bucket | Core Question | Example Metrics | Evaluation Method |
|---|---|---|---|
| **Domain Capability** | Does the model solve the cognitive task? | pass@k, unit test assertions, math accuracy | Sandbox code execution, regex |
| **Generation Quality** | Is prose factually faithful and safe? | Grounding score, hallucination rate, toxicity | Rubric-guided LLM judge |
| **Instruction Following** | Were formatting constraints obeyed? | Valid JSON/Pydantic schema, length bounds | Deterministic parser |
| **Cost & Latency** | Can we serve it economically within SLOs? | TTFT (Time to First Token), TPOT, \$ / 1M tokens | Serving engine Prometheus metrics |

## Functional correctness: unbiased pass@k

When evaluating code or mathematical tasks, syntax does not matter; execution does. Generating $k$ samples and checking if at least one passes has high variance. Chen et al. (2021) derived the unbiased hypergeometric estimator by generating $n$ samples ($n \ge k$) and observing $c$ passing solutions:

$$
\text{pass}@k = \mathbb{E}\left[ 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}} \right] = 1 - \prod_{i=1}^k \frac{n - c - i + 1}{n - i + 1}
$$

If $n - c < k$, then $\text{pass}@k \equiv 1.0$.

Worked numeric example ($n = 10$ samples, $c = 3$ passing, $n - c = 7$ failing):
- **For $k = 1$**:
  $$
  \text{pass}@1 = 1 - \frac{\binom{7}{1}}{\binom{10}{1}} = 1 - \frac{7}{10} = \mathbf{0.300}\quad (30.0\%)
  $$
- **For $k = 5$**:
  $$
  \binom{7}{5} = 21, \quad \binom{10}{5} = 252 \implies \text{pass}@5 = 1 - \frac{21}{252} = 1 - \frac{1}{12} \approx \mathbf{0.9167}\quad (91.7\%)
  $$

## Exact Match (EM) vs semantic metrics

| Metric | Modality | Handles Paraphrasing? | Sensitive to Negation? | Computational Cost |
|---|---|---|---|---|
| **Normalized EM** | String equality | No | Yes (100% strict) | Microseconds (CPU) |
| **pass@k** | Code execution | Yes (logic-based) | Yes (tests fail) | Milliseconds to seconds (sandbox) |
| **BLEU / ROUGE** | N-gram overlap | No (penalizes synonyms) | No (severe blindspot) | Microseconds (CPU) |
| **BERTScore** | Token embeddings | Yes (cosine matching) | Partially | Tens of ms (GPU forward pass) |

### BERTScore formulation
Token-level greedy cosine matching between contextual embeddings of reference $x$ and candidate $\hat{x}$:

$$
R_{\text{BERT}} = \frac{1}{|x|} \sum_{i \in x} \max_{j \in \hat{x}} (x_i^\top \hat{x}_j), \qquad
P_{\text{BERT}} = \frac{1}{|\hat{x}|} \sum_{j \in \hat{x}} \max_{i \in x} (x_i^\top \hat{x}_j)
$$

$$
F1_{\text{BERT}} = 2 \times \frac{P_{\text{BERT}} \times R_{\text{BERT}}}{P_{\text{BERT}} + R_{\text{BERT}}}
$$

## AI-as-a-judge: biases and debiasing

| Judge Bias | Observed Phenomenon | Mitigation Strategy |
|---|---|---|
| **Position Bias** | Judge favors Candidate 1 as much as 60% to 70% of the time | **Bidirectional order swapping**: Evaluate `(A, B)` and `(B, A)`; require agreement |
| **Verbosity Bias** | Higher scores awarded to long, formatted responses with zero extra facts | Explicit length penalty in rubric; reward concise answers |
| **Self-Preference** | Model favors completions from its own architectural lineage (+10% to +15% delta) | Multi-judge ensembling across model families; specialized independent judges |

### Bidirectional swap reconciliation logic
- Pass 1: Present `(A, B)` $\to$ Record decision $V_1 \in \{A, B\}$.
- Pass 2: Present `(B, A)` $\to$ Record decision $V_2 \in \{A, B\}$.
- **Reconciliation**:
  $$
  \text{Win}_A \iff (V_1 = A) \land (V_2 = A)
  $$
  $$
  \text{Win}_B \iff (V_1 = B) \land (V_2 = B)
  $$
  $$
  \text{Tie} \iff \text{otherwise}
  $$

## Calibrating judges: Cohen’s kappa

Measures inter-rater agreement between automated judge and human expert beyond chance:

$$
\kappa = \frac{p_o - p_e}{1 - p_e}
$$

where $p_o$ is observed fractional agreement, and $p_e$ is expected chance agreement from marginal probabilities:
$$
p_e = (p_{\text{human,1}} \times p_{\text{judge,1}}) + (p_{\text{human,0}} \times p_{\text{judge,0}})
$$

Worked numeric example ($N = 100$ items: 70 both pass, 15 both fail, 5 human pass/judge fail, 10 human fail/judge pass):
- $p_o = (70 + 15) / 100 = \mathbf{0.850}$ (85.0% raw agreement).
- $p_e = (0.75 \times 0.80) + (0.25 \times 0.20) = 0.600 + 0.050 = \mathbf{0.650}$.
- $\kappa = \frac{0.850 - 0.650}{1.000 - 0.650} = \frac{0.200}{0.350} \approx \mathbf{0.571}$ ("Moderate agreement").

Rule of thumb: **Do not deploy an automated AI judge with $\kappa < 0.65$.**

## Comparative evaluation: Elo & Bradley-Terry

### Elo rating system
Expected win probability for Model A against Model B:

$$
E_A = \frac{1}{1 + 10^{(R_B - R_A)/400}}, \qquad E_B = 1 - E_A
$$

Rating update after match outcome $S_A \in \{1.0, 0.5, 0.0\}$:

$$
R'_A = R_A + K \times (S_A - E_A), \qquad R'_B = R_B + K \times (S_B - E_B)
$$

Worked numeric example ($R_A = 1200$, $R_B = 1100$, $K = 32$):
- Rating difference: $R_B - R_A = -100$.
- $10^{-100/400} = 10^{-0.25} \approx 0.56234$.
- $E_A = 1 / (1 + 0.56234) \approx \mathbf{0.6401}$ (64.0% expected win rate).
- If Model A wins ($S_A = 1.0$):
  $$
  \Delta R_A = 32 \times (1.0 - 0.6401) = \mathbf{+11.52\ \text{points}} \implies R'_A = 1211.52
  $$
  $$
  \Delta R_B = -\mathbf{11.52\ \text{points}} \implies R'_B = 1088.48
  $$

### Bradley-Terry formulation
$$
P(A > B) = \frac{e^{r_A}}{e^{r_A} + e^{r_B}} = \sigma(r_A - r_B)
$$

Identical to the negative log-likelihood reward model loss in Module 3C (RLHF / DPO):
$$
\mathcal{L}_{\text{RM}} = -\mathbb{E} \left[ \ln \sigma(r(y_w) - r(y_l)) \right]
$$

## Contamination detection

1. **13-Gram Exact Match Rule**: A continuous sequence of 13 words shared between a pretraining document and an evaluation test set indicates verbatim leakage.
2. **Perplexity Perturbation Test**:
   $$
   \text{PPL} = \exp(\text{CrossEntropyLoss})
   $$
   A memorized question exhibits $\text{PPL} \le 1.5$. When entity names and numbers are perturbed without changing syntax, a contaminated model displays a **$4\times$ to $10\times$ perplexity spike**, proving rote memorization.

## Slicing and Simpson’s paradox

Never evaluate solely on aggregate accuracy. Shifting query difficulty distributions create statistical reversals:

| Evaluation Slice | Baseline Model 1 | Candidate Model 2 | Slice Winner |
|---|---|---|---|
| **Slice A: Easy Short Queries** | 18 / 20 = **90.0%** | 68 / 80 = **85.0%** | **Model 1 (+5.0%)** |
| **Slice B: Hard Multi-Step** | 40 / 80 = **50.0%** | 9 / 20 = **45.0%** | **Model 1 (+5.0%)** |
| **Overall Aggregate** | 58 / 100 = **58.0%** | 77 / 100 = **77.0%** | **Model 2 (+19.0%?!)** |

Model 2 appears to win by +19% in aggregate only because 80% of its test split was easy, despite losing on every single individual slice. Always report sliced scorecards.

## Sample size & standard error

Binomial standard error for accuracy proportion $p$ over sample size $n$:

$$
\text{SE} = \sqrt{\frac{p(1 - p)}{n}}
$$

Margin of error at 95% confidence ($\pm 1.96 \times \text{SE}$):

At baseline accuracy $p = 0.80$ ($p(1 - p) = 0.160$):
- **$n = 100$**: $\text{SE} = \sqrt{0.160/100} = \mathbf{0.0400}$ (4.00%). 95% CI is $\pm 7.84\%$ (width **15.68%**).
- **$n = 400$**: $\text{SE} = \sqrt{0.160/400} = \mathbf{0.0200}$ (2.00%). 95% CI is $\pm 3.92\%$ (width **7.84%**).
- **$n = 1000$**: $\text{SE} = \sqrt{0.160/1000} \approx \mathbf{0.01265}$ (1.265%). 95% CI is $\pm 2.48\%$ (width **4.96%**).

**The Inverse Square Law**: Detecting a $3\times$ smaller performance difference requires $(3)^2 = \mathbf{9\times\ \text{to}\ 10\times\ \text{more samples}}$.

## Build vs Buy break-even economics

Fixed GPU lease cost ($C_{\text{gpu}}$) versus variable commercial API token price ($P_{\text{api}}$):

$$
V_{\text{break-even}} = \frac{C_{\text{gpu}}}{P_{\text{api}}}
$$

- **8B Model Tier**:
  - Leased GPU instance (1× NVIDIA L4 / A10G): \$0.80/hour $\implies C_{\text{gpu}} = 0.80 \times 24 \times 30 = \mathbf{576.00\ \text{USD/month}}$.
  - Managed API rate: \$0.30 per 1M blended tokens ($0.30 \times 10^{-6}\ \text{USD}$ per token).
  - Break-Even Volume:
    $$
    V_{\text{break-even}} = \frac{576.00}{0.30 \times 10^{-6}} = \mathbf{1.92\ \text{billion tokens per month}}
    $$
- **70B Model Tier**:
  - Leased GPU cluster (2× H100 SXM): \$6.00/hour $\implies C_{\text{gpu}} = 6.00 \times 24 \times 30 = \mathbf{4{,}320.00\ \text{USD/month}}$.
  - Managed 70B API rate: \$1.80 per 1M blended tokens ($1.80 \times 10^{-6}\ \text{USD}$ per token).
  - Break-Even Volume:
    $$
    V_{\text{break-even}} = \frac{4{,}320.00}{1.80 \times 10^{-6}} = \mathbf{2.40\ \text{billion tokens per month}}
    $$
