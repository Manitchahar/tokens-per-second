## Task 1 · Dual-Index Ingestion (Sparse + Dense)

In the notebook, load the 50-document technical knowledge base and build both index representations:
1. **BM25 Lexical Index:** Tokenize document strings with lowercase normalization and initialize `BM25Okapi`.
2. **Dense Semantic Index:** Load `sentence-transformers/all-MiniLM-L6-v2` ($d = 384$), encode all 50 documents with $L_2$ normalization, and insert them into a `faiss.IndexFlatIP` inner-product index.

```python
# Task 1 snippet
from rank_bm25 import BM25Okapi
from sentence_transformers import SentenceTransformer
import faiss

# BM25 Inverted Index
tokenized_corpus = [doc["text"].lower().replace("_", " ").split() for doc in CORPUS]
bm25 = BM25Okapi(tokenized_corpus)

# FAISS Dense Index
embed_model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cuda")
corpus_embeddings = embed_model.encode([doc["text"] for doc in CORPUS], normalize_embeddings=True)
index = faiss.IndexFlatIP(corpus_embeddings.shape[1])
index.add(corpus_embeddings)
```

**Expected output:**
```
FAISS index built: 50 vectors of dimension 384.
```

**How to read it:** Notice how fast ingestion is. Generating 384-dimensional embeddings for 50 documents on a T4 GPU takes under **0.5 seconds**. The total index size is $50 \times 384 \times 4\text{ bytes} \approx 76.8\text{ KB}$, fitting instantly into GPU SRAM.

## Task 2 · Benchmark Recall@5 (BM25 vs Dense vs Hybrid)

Execute the 30-question evaluation benchmark against three distinct retrieval configurations:
1. `search_bm25(query, top_k=5)`
2. `search_dense(query, top_k=5)`
3. `search_hybrid_rrf(query, top_k=5, k_rrf=60)`

**Expected results:**
```
--- STAGE 1 RETRIEVAL BENCHMARK ---
BM25 Sparse          Recall@5: 23/30 = 76.7%
Dense Vector         Recall@5: 24/30 = 80.0%
Hybrid (RRF)         Recall@5: 28/30 = 93.3%
```

**How to read it:**
- **Where BM25 wins:** Query 1 (*"What causes ERR_NCCL_TIMEOUT_502 and how is it mitigated?"*). BM25 achieves Rank 1 because the alphanumeric string `ERR_NCCL_TIMEOUT_502` has an immense IDF score. The dense embedding model places it at Rank 8 because the vector model blurs the specific error code into general distributed communication.
- **Where Dense wins:** Query 11 (*"Why do language models generate text one word at a time instead of all at once?"*). Dense vector search achieves Rank 1 because it understands the conceptual relationship to *autoregressive decoding*. BM25 completely misses this query (0/5) because the target document contains words like *"autoregressive"*, *"token"*, and *"forward pass"*, sharing zero tokens with *"one word at a time"*.
- **The Hybrid Breakthrough:** By combining both with Reciprocal Rank Fusion ($k = 60$), Hybrid retrieval captures **93.3%** of all relevant documents — a dramatic jump over either individual system.

## Task 3 · Add the Cross-Encoder Reranker

Now introduce Stage 2 of the retrieval funnel. Load `cross-encoder/ms-marco-MiniLM-L-6-v2`.

Modify the search function to:
1. Cast a wide net: retrieve the **top 20 candidate chunks** using Hybrid RRF.
2. Form 20 `[query, candidate_document]` pairs.
3. Compute joint bidirectional cross-attention scores with the cross-encoder.
4. Sort by cross-encoder score and keep the **top 5**.

```python
# Task 3 snippet
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2", device="cuda")
candidate_ids = search_hybrid_rrf(query, top_k=20)
pairs = [[query, doc_map[cid]] for cid in candidate_ids]
scores = reranker.predict(pairs)
top_5_ids = [candidate_ids[i] for i in np.argsort(-scores)[:5]]
```

**Expected results:**
```
--- STAGE 2 RERANKED BENCHMARK ---
Hybrid + Reranker    Recall@5: 29/30 = 96.7%
```

**How to read it:** The cross-encoder pushes recall up to **96.7%**. More importantly, inspect the Rank 1 position: across virtually every query, the exact target document is promoted to **Rank 1**. The cross-encoder eliminates false-positive chunks that scored high in BM25 due to coincidental keyword repetition.

## Check Yourself: Five Critical Questions

Before completing the lab, verify that you can answer these five core systems questions based on your measurements:

1. **Why did BM25 fail on the autoregressive decoding query?**
   *Answer:* Because BM25 relies on exact term overlap. When a user asks an abstract question using natural conversational synonyms, the query contains zero vocabulary in common with the technical document's formal terminology.
2. **Why did dense vector search fail on `ERR_NCCL_TIMEOUT_502`?**
   *Answer:* Sentence-transformers tokenize rare alphanumeric error codes into multiple subword tokens (e.g., `_ERR`, `_NC`, `CL`, `502`), and mean-pooling smooths them into a generic "networking error" embedding that clusters with dozens of other unrelated communication errors.
3. **What is the computational cost of running the Cross-Encoder on 20 pairs?**
   *Answer:* Scoring 20 pairs with a 22M parameter cross-encoder on a T4 GPU takes roughly 12 milliseconds. This is well within typical 50 ms interactive TTFT budgets.
4. **How many prompt tokens did the top-3 retrieved chunks add to the generator prefill?**
   *Answer:* Each chunk is approximately 40–60 tokens. Three chunks add ~150 prompt tokens. On a 1.5B model, prefilling 150 tokens on a T4 GPU takes under 4 milliseconds.
5. **What would happen if you fed 50 candidate chunks directly to the generator without reranking?**
   *Answer:* Prompt tokens would balloon by 2,500 tokens, increasing TTFT latency, bloating KV cache memory, and increasing the risk of the model suffering from *lost in the middle* attention degradation.

<KeyNotes>
  1. Dense embeddings and BM25 have **orthogonal failure modes**: BM25 excels at exact codes, names, and numbers; dense embeddings excel at paraphrased semantics.
  2. **Reciprocal Rank Fusion (RRF)** combines dense and sparse ranks with zero score calibration, achieving **93.3% Recall@5** on our 30-query benchmark compared to ~77–80% for individual retrievers.
  3. A **Cross-Encoder reranker** (`ms-marco-MiniLM-L-6-v2`) provides full token-to-token cross-attention, boosting Recall@5 to **96.7%** and promoting the true ground truth to Rank 1.
  4. The **Two-Stage Funnel** (retrieve 20 via hybrid, rerank to 5) achieves high factual precision while keeping generator prompt length tightly bounded.
  5. Grounded generation with `Qwen2.5-1.5B-Instruct` completely eliminates factual hallucinations on specific technical specifications, producing verifiable citations for every claim.
</KeyNotes>
