## What you will do in the notebook

### 1. Confirm the GPU

You will ask PyTorch whether a GPU is visible and what it is. Expect **Tesla T4**, about **15 GB** of memory and **40 SMs**. An SM is one of the GPU's independent processing blocks; Module 02 opens one up.

### 2. Read `nvidia-smi`

`nvidia-smi` is the GPU's dashboard, and the first command every inference engineer types on a new machine. You will learn to read these fields:

| Field | Meaning | Why you care |
|---|---|---|
| **Memory-Usage** | GPU memory used / total | Model weights and KV cache must fit here. Running out = crash (OOM). |
| **GPU-Util** | % of time any kernel was running | A rough "is it busy" signal. 100% does *not* mean efficient (Module 12). |
| **Pwr: Usage/Cap** | Power draw in watts | Busy, efficient kernels draw more power. |
| **Temp** | Chip temperature | Hot GPUs slow themselves down (throttle). |

### 3. Numbers on the GPU

You will create a 4096 × 4096 grid of numbers (a <Term t="tensor">tensor</Term>) and copy it into GPU memory with `.to("cuda")`. You will check that it takes exactly 4096 × 4096 × 4 bytes = 67 MB. **Every number costs bytes.** This is the habit that makes memory math, later, feel easy.

### 4. The race, and the #1 benchmarking bug

You will multiply two big matrices on the CPU and on the GPU and time both. The GPU will win by 10× to 100×.

But there is a trap, and you will fall into it on purpose. When Python launches work on the GPU, it **does not wait**: it queues the job and returns immediately. If you stop your stopwatch then, you measure how long it took to *ask*, not how long it took to *do*.

```python
torch.cuda.synchronize()          # wait until the GPU is idle
t0 = time.perf_counter()
c = a_gpu @ b_gpu                 # queued, returns instantly
torch.cuda.synchronize()          # wait until the multiply is really done
elapsed = time.perf_counter() - t0
```

<Callout type="mentor">
  Every benchmark in this course, and in your career, needs this line. When a GPU number looks too good to be true, the first question to ask is *"did they synchronize?"*
</Callout>

### 5. Half precision

You will rerun the multiply in 16-bit numbers (`float16`). Half the bytes, and the GPU switches on its **tensor cores**, the special matrix hardware. Expect several times more speed. This is why every LLM is served in 16-bit or lower.

<KeyNotes>
  1. Colab gives you a free **T4** GPU: 16 GB of memory, 40 SMs, about 65 TFLOP/s in FP16. Enough for every lab.
  2. `nvidia-smi` shows GPU memory usage, utilization, power and temperature.
  3. Tensors live in a specific memory (CPU RAM or GPU memory). `.to("cuda")` copies them to the GPU.
  4. Every number costs bytes: FP32 = 4, FP16/BF16 = 2.
  5. GPU work is **asynchronous**. Always call `torch.cuda.synchronize()` before stopping a timer.
  6. 16-bit math on tensor cores is several times faster than 32-bit.
</KeyNotes>
