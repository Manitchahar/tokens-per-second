At the end of 2018 the scoreboard was clear. BERT, playing the masked-word game, beat the left-to-right GPT-1 at almost every reading task, and the ablation in the last lesson showed why: seeing both sides matters.

But look at what using BERT actually involves. For every task you want, you need three things: a **labelled dataset** for that task, a **new head** bolted on top, and a **finetuning run** that produces a separate copy of the model. Sentiment, entailment, question answering, named entities: four tasks, four datasets, four models. And there is a whole class of things it simply cannot do, because BERT cannot write a sentence.

In February 2019, a team at OpenAI published a paper with a provocative title, *Language Models are Unsupervised Multitask Learners*. Its claim: you do not need any of those three things. Train a large enough *left-to-right* model on varied enough text, and it will perform tasks it was never trained on, if you just write the task down. That model was GPT-2.

## The wall: one task, one dataset, one model

The paper starts from a complaint about the whole field. Systems trained on one labelled dataset for one task become what the authors call narrow experts: excellent on their benchmark, brittle as soon as the inputs drift. The standard cure is **multitask learning**: train one model on many labelled tasks at once. But that needs a labelled dataset per task, and at the time the largest multitask efforts combined only a few dozen. If you need thousands of examples of each task, you will never have enough tasks.

So the bottleneck is not the model. It is that **every task has to be specified by a labelled dataset.** Is there another way to tell a model what you want?

## The bet: write the task down

Formally, a single-task model learns $p(\text{output} \mid \text{input})$. A general system should learn $p(\text{output} \mid \text{input}, \text{task})$: the same input can call for different outputs depending on the task. The question is how to give it the task.

GPT-2's answer is almost embarrassingly simple: **as text, in the same stream.** "Translate to French: good morning →" is a task, an input and a request for an output, all written in language. A model of language is already a model of $p(\text{next text} \mid \text{previous text})$. If the previous text describes a task, the most likely continuation is the task's answer.

Would a model really learn that, without ever being told? The paper's argument: **the web is full of tasks written out in plain language.** People write "X means Y in French" on language forums, put a question and its answer on quiz pages, and end long posts with "TL;DR:" and a one-line summary. A model trained to predict such text has to learn, implicitly, how to translate, answer and summarise, because those skills lower its loss on exactly those passages. Nobody labels them as tasks. They are just text.

This is the next-word game from lesson 1, taken seriously: no head, no finetuning, no labelled data. A model that performs a task with no examples and no weight updates for it is working <Term t="zero-shot">zero-shot</Term>.

## Then derive it properly

### The objective: exactly lesson 1

There is nothing new in GPT-2's loss. It is the causal next-token objective of lesson 1, scored with the cross-entropy of lesson 2:

$$
\mathcal{L} = -\frac{1}{N} \sum_{t} \ln p_\theta(x_t \mid x_{<t})
$$

Every token of WebText is a target, every forward pass grades every position, and the causal mask keeps it honest. The novelty is entirely in *what* it was trained on, *how big* it was, and *how it was used*.

### WebText: quality without labels

Common Crawl, a public scrape of billions of web pages, already existed. But much of it is spam, boilerplate and machine-generated junk; the GPT-2 authors found it had serious quality problems. Filtering it by hand was out of the question. Their shortcut was to borrow human judgement that already existed:

1. Collect every outbound link posted to Reddit that received **at least 3 karma**, a weak signal that some people found the page interesting, educational or funny. That gave about **45 million links**.
2. Extract the text, deduplicate and clean it.
3. **Remove every Wikipedia page**, because Wikipedia is used inside many test sets, and overlap would inflate the results.

The result, <Term t="webtext">WebText</Term>, was **slightly over 8 million documents, 40 GB of text**. It is tiny by modern standards — lesson 1 quoted 15 trillion tokens for Llama 3 — but it was deliberately diverse: news, how-to guides, fiction, forum threads, code.

<Callout type="pitfall" title="Upvotes are a filter, not a guarantee">
  "At least 3 karma" selects pages people liked, not pages that are true, balanced or safe. The model inherits whatever those pages contain, including the biases of the community doing the voting. Every later data pipeline has the same tension between cheap automatic filters and what you actually want the model to learn (Module B6).
</Callout>

### Byte-level BPE: 50,257 tokens and no unknowns

You built BPE in *Tokens & tokenizers* (Module 03): start from a base alphabet and repeatedly merge the most frequent adjacent pair. The question is what the base alphabet should be.

- **Unicode characters?** There are well over a hundred thousand of them. Using them all as the base would blow up the vocabulary before a single merge.
- **Words, as earlier systems did?** Then anything not in the word list becomes an "unknown" token and its information is lost. BERT's WordPiece has an `[UNK]` token for exactly this.
- **Bytes.** Every string in every language, every emoji and every binary blob is a sequence of UTF-8 bytes, and there are only 256 possible bytes.

GPT-2 runs <Term t="byte-level-bpe">byte-level BPE</Term>:

$$
\underbrace{256}_{\text{byte tokens}} + \underbrace{50{,}000}_{\text{learned merges}} + \underbrace{1}_{\texttt{<|endoftext|>}} = 50{,}257
$$

Frequent words end up as single tokens; rare words split into pieces; in the worst case text falls back to one token per byte. **Any string can be encoded, so there is no unknown token at all**, which is what lets a single model read the whole messy web. One refinement from the paper: merges were not allowed to cross character categories, so the vocabulary does not waste entries on "dog.", "dog!" and "dog?". Every modern tokenizer you will meet, including Llama 3's 128,256-token one, keeps the byte fallback.

### The model: GPT-1, bigger, with the norms moved

GPT-2 is a <Term t="decoder-only">decoder-only</Term> transformer — the causal stack you built in Module 03 — in four sizes:

| Paper's label | Released as | Layers | Width $d$ | Heads | FP16 weights | KV cache per token (FP16) |
|---|---|---|---|---|---|---|
| 117M | 124M | 12 | 768 | 12 | 0.25 GB | 36 KiB |
| 345M | 355M | 24 | 1,024 | 16 | 0.71 GB | 96 KiB |
| 762M | 774M | 36 | 1,280 | 20 | 1.55 GB | 180 KiB |
| 1542M | 1.5B | 48 | 1,600 | 25 | 3.12 GB | 300 KiB |

Every head is 64 numbers wide (${}768/12$, ${}1{,}600/25$). All four read up to **1,024 tokens** (GPT-1: 512), through a learned position table of 1,024 rows, which you met in *Embeddings & positions*. Training used batches of 512 sequences. The released checkpoints are labelled 124M, 355M, 774M and 1.5B because the paper's own table undercounted; the architectures are the same.

<Callout type="math" title="Where 124M comes from">
  - Token embeddings: ${}50{,}257 \times 768 = 38{,}597{,}376$. Position embeddings: ${}1{,}024 \times 768 = 786{,}432$.
  - One block: attention $(768 \times 2{,}304 + 2{,}304) + (768^2 + 768) = 2{,}362{,}368$; MLP $(768 \times 3{,}072 + 3{,}072) + (3{,}072 \times 768 + 768) = 4{,}722{,}432$; two LayerNorms ${}4 \times 768 = 3{,}072$. Total **7,087,872**, and 12 blocks make **85,054,464**.
  - One final LayerNorm: ${}1{,}536$. The output head reuses the token embedding matrix (tied embeddings), so it adds nothing.

  $$
  38{,}597{,}376 + 786{,}432 + 85{,}054{,}464 + 1{,}536 = 124{,}439{,}808
  $$

  Notice that one GPT-2 block has exactly as many weights as one BERT-Base layer (7,087,872): same width, same MLP. The two models really are one machine doing two jobs; the difference is the mask and the game.
</Callout>

The architectural changes from GPT-1 are small but lasting:

- **<Term t="pre-norm">Pre-norm</Term>.** The original transformer and GPT-1 applied LayerNorm *after* each residual add ("post-norm"). GPT-2 moves it to the *input* of each sub-block: normalise the copy that goes into attention or the MLP, and add the result back to an untouched residual stream, as you built in *The MLP, RMSNorm & the residual stream*. An extra LayerNorm sits after the final block. The residual stream now has a clean path from the embeddings to the output, which makes deep stacks much easier to train.
- **Scaled initialisation.** The weights of layers that write into the residual stream are scaled down at initialisation by ${}1/\sqrt{N}$, where $N$ is the number of residual layers, so the stream does not grow as more blocks add to it.
- **Bigger vocabulary and context**, as above.

Every model you will serve in this course — Llama, Qwen, Mistral — is still a pre-norm decoder with a byte-fallback BPE tokenizer. They swapped LayerNorm for RMSNorm and learned positions for RoPE, but the skeleton is GPT-2's.

### Using it: the prompt is the task

To make GPT-2 do a task, the authors wrote the task as text and let it continue:

- **Summarisation:** paste a news article, append `TL;DR:`, and generate 100 tokens with top-k sampling at $k = 2$ (*Logits to tokens: sampling*), keeping the first three sentences.
- **Translation:** prime the context with example pairs written as `english sentence = french sentence`, then end with a new `english sentence =`.
- **Question answering:** give a document and the conversation so far, and end with `A:`.

No weights change. The only "training" is the shape of the prompt. Module B1 turns this into a craft.

### What it achieved, honestly

The headline result is on **language modelling** itself: tested zero-shot on eight standard benchmarks, without training on any of them, GPT-2 improved the state of the art on **7 of the 8**. (The exception was the One Billion Word benchmark, which has its sentences shuffled, destroying the long-range structure GPT-2 was good at.)

| Benchmark (zero-shot) | 124M | 355M | 774M | 1.5B | Previous best |
|---|---|---|---|---|---|
| LAMBADA perplexity ↓ | 35.13 | 15.60 | 10.87 | **8.63** | 99.8 |
| LAMBADA accuracy ↑ | 45.99% | 55.48% | 60.12% | **63.24%** | 59.23% |
| WikiText-103 perplexity ↓ | 37.50 | 26.37 | 22.05 | **17.48** | — |

LAMBADA tests whether a model can predict the last word of a passage, which requires using context from far back. Read the rows from left to right: **every metric improves at every size, with no sign of levelling off.** The authors also noted that even the 1.5B model still underfit WebText. Bigger was going to be better still — that is where Module 3B picks up.

On real tasks the picture was more mixed, and the paper says so:

- **Reading comprehension (CoQA):** about 55 F1, matching or beating three of four baseline systems that had been trained on over 127,000 labelled examples, while GPT-2 saw none.
- **Summarisation:** the summaries only began to approach classic neural baselines, and barely beat picking three random sentences from the article. But removing the `TL;DR:` hint made results clearly worse — evidence that the model was responding to the task description.
- **Translation:** about 5 BLEU from English to French, poor in absolute terms, and 11.5 from French to English, which was remarkable given that WebText was filtered to be English.
- **Open-domain questions:** the 1.5B model answered about 4% of Natural Questions exactly right; poor in absolute terms, but more than five times the smallest model's score.

So GPT-2 was not yet a useful assistant. What it showed was the *direction*: tasks emerge from plain next-word prediction, they work with no labelled data at all, and they get steadily better with scale.

<Callout type="intuition" title="Why the next-word game generalises">
  BERT is trained to fill blanks in text it is given, so to use it you must reshape your task into something a head can read off its vectors. GPT-2 is trained to *continue* text, and almost any task can be written as "here is some text, continue it". The objective and the interface are the same thing. That is the property lesson 5 argues won the decade.
</Callout>

<Callout type="pitfall" title="Did it just memorise the test sets?">
  A model trained on 8 million web pages might simply have read the benchmarks. The authors checked: they measured how many 8-word sequences of each test set also appeared in WebText, found the overlap was small, and showed that removing overlapping examples changed results only slightly. They also flagged that their own WebText overlapped with some test sets less than the benchmarks' own training sets did. Lesson 2's warning applies: whenever a perplexity looks too good, check for contamination first.
</Callout>

<Callout type="real" title="GPT-2 from an inference engineer’s chair">
  GPT-2 is the ancestor of the workload this course is about: a decoder that produces **one token per forward pass**, reusing every earlier token's keys and values. Its KV cache per token is

  $$
  2\ (\text{K and V}) \times L \times d \times 2\ \text{bytes}
  $$

  because every one of its heads has its own keys and values (full multi-head attention, *Multi-head attention, MQA & GQA*). For the 124M model: ${}2 \times 12 \times 768 \times 2 = 36{,}864$ bytes = 36 KiB per token, so 36 MiB for a full 1,024-token context. For the 1.5B model: ${}2 \times 48 \times 1{,}600 \times 2 = 307{,}200$ bytes = **300 KiB per token** — more than Llama-3.1-8B's 128 KiB, for a model five times smaller. Grouped-query attention is the reason the newer, bigger model is cheaper to remember.

  And the 124M model, at 250 MB in FP16, is the "hello world" of LLM engineering: small enough for a laptop, real enough to profile. The lab uses it.
</Callout>

  2. A model of $p(\text{next text} \mid \text{previous text})$ already covers $p(\text{output} \mid \text{input}, \text{task})$ when the task is written as text. Doing a task with no examples and no weight updates is **zero-shot**.
  3. **WebText:** outbound Reddit links with at least 3 karma (~45M), deduplicated and cleaned, Wikipedia removed: slightly over 8M documents, 40 GB.
  4. **Byte-level BPE:** 256 bytes + 50,000 merges + 1 end-of-text token = **50,257** tokens. Any string encodes, so there is no unknown token.
  5. Four sizes: 124M (12 × 768), 355M (24 × 1,024), 774M (36 × 1,280), 1.5B (48 × 1,600); heads of 64; context 1,024. The paper's table says 117M/345M/762M/1542M.
  6. **Pre-norm:** LayerNorm moved to the input of each sub-block, plus a final LayerNorm. Every modern decoder still does this (with RMSNorm).
  7. Zero-shot it beat the state of the art on 7 of 8 language-modelling benchmarks (LAMBADA perplexity 99.8 → 8.63), and every metric improved smoothly with size; real tasks worked, but often far below supervised systems.
  8. KV cache per token for GPT-2 is ${}2 L d \times 2$ bytes: 36 KiB for 124M, 300 KiB for 1.5B. Staged release: 124M in February 2019, 1.5B in November 2019.
</KeyNotes>
