Generating 50,000 synthetic instruction pairs using an LLM takes only a few hours. But if you take those raw outputs and immediately train a model on them, you are playing Russian roulette with your model's intelligence.

Unverified synthetic datasets are plagued by subtle, toxic failure modes:
- **Tautological explanations**: When prompted to explain a concept, models often define a term using the term itself (*"An atomic transaction is atomic because it possesses atomicity"*).
- **Subtle off-by-one errors in code**: Synthetic code snippets look visually convincing and compile cleanly, but fail on edge cases like empty lists or negative indexes.
- **Sycophancy**: The synthetic assistant agrees with incorrect premises in the prompt rather than correcting the user.
- **Format hallucinations**: The model produces pseudo-JSON containing unescaped quotes or trailing commas that crash downstream parsers.

Worse, when models are trained recursively on data generated by preceding generations of models, a catastrophic statistical failure known as <Term t="model-collapse">model collapse</Term> takes place: the distribution's tails vanish, its variance contracts, and the model eventually degenerates into repetitive gibberish.

In this lesson, we build the **Three-Tier Verification Funnel** to filter synthetic data, derive the mathematics of model collapse from first principles, and establish the anchor rules required to keep models robust over time.

## The Three-Tier Verification Funnel

You cannot afford to have human experts manually inspect 50,000 synthetic pairs, and running a massive 405B parameter model as a judge on every single candidate is too expensive.

Production data engineering uses a **tiered funnel**: fast, cheap heuristic filters discard the obvious garbage first, followed by deterministic code execution, reserving expensive LLM judges only for the surviving candidates.

  </Step>

  <Step title="3. Gen 1: Minor tail erosion">
    When Generation 1 trains on samples drawn from Generation 0, low-probability tail events are under-sampled. The model learns the common modes well, but **rare tail events begin to erode**.
  </Step>

  <Step title="4. Gen 3: Early collapse & mode loss">
    By Generation 3, **early collapse** sets in. Variance contracts significantly. The model forgets how to handle rare edge cases, legal jargon, or uncommon programming idioms, collapsing into generic, safe responses.
  </Step>

  <Step title="5. Gen 5: Late collapse into gibberish">
    Without human grounding, Generation 5 experiences **late collapse**. The distribution collapses into a single degenerate spike. The model loses coherence entirely, emitting repetitive loops of nonsense text.
  </Step>

  <Step title="6. The cure: Human anchor & tests">
    The collapse is prevented by **anchoring every dataset with 20% to 40% authentic human data** and enforcing strict rejection sampling via deterministic code execution. Ground truth prevents variance erosion.
  </Step>
</Scrolly>

### Tier 1: Heuristic & Rule-Based Filters (Cost: &lt; \$0.00001 / sample)
The first filter runs locally on CPU in microseconds per row. It eliminates malformed outputs before any neural network or sandbox is invoked:

1. **Length Bounds**: Prune any response shorter than 15 tokens (which are usually dismissive refusals like *"I cannot help with that"*) or longer than your target context budget (e.g. 2,048 tokens).
2. **Repetition and Compression Ratio (zlib)**: When an autoregressive model gets trapped in an attention loop, it repeats phrases like `"and then and then and then"`.
   Compress the string using Python's standard `zlib`:
   $$
   C_{\text{ratio}} = \frac{\text{len}(\text{zlib.compress}(\text{text.encode()}))}{\text{len}(\text{text.encode()})}
   $$
   Normal English text has a compression ratio between 0.35 and 0.65. A repeating loop compresses dramatically ($C_{\text{ratio}} < 0.20$), while high-entropy character gibberish fails to compress ($C_{\text{ratio}} > 0.85$). Discard both extremes.
3. **Language Identification**: Run a lightweight FastText classifier. If your instruction dataset is meant to be English, immediately drop any candidate where $P(\text{lang} = \text{"en"}) < 0.95$.
4. **Pattern & Refusal Blacklists**: Use regular expressions to prune conversational chatter:
   - Apologies: `r"(I apologize|As an AI language model|As an artificial intelligence)"`
   - Sycophantic openers: `r"^(Sure!|Certainly!|Here is the answer you requested:)"`

### Tier 2: Functional Verification (Ground Truth Execution)
Heuristic filters verify that text *looks* normal, but cannot tell whether an answer is *factually correct*.

Whenever possible, replace human judgment with **deterministic execution**:

```python
# Functional Verification Architecture for Code Generation
import subprocess
import tempfile

def verify_python_code(code_str: str, unit_test_str: str, timeout_sec: int = 2) -> bool:
    """Execute code + unit test in an isolated subprocess sandbox."""
    full_program = f"{code_str}\n\n{unit_test_str}\n"
    with tempfile.NamedTemporaryFile("w", suffix=".py", delete=True) as f:
        f.write(full_program)
        f.flush()
        try:
            res = subprocess.run(
                ["python", f.name],
                capture_output=True,
                text=True,
                timeout=timeout_sec
            )
            return res.returncode == 0
        except subprocess.TimeoutExpired:
            return False  # Prune infinite loops!
        except Exception:
            return False
```

1. **Code Execution**: Generate not just the code, but also a set of 3 unit tests. Run the program in a sandbox. If the program raises an `AssertionError`, times out, or fails `mypy` type checking, **discard the candidate immediately**.
2. **Mathematical Solvers**: If generating math solutions, extract the final numerical answer or algebraic expression and verify it against a symbolic math engine like `SymPy`.
3. **JSON Schema Validation**: If training for tool use or structured output (Module 26), pass the synthetic response through `pydantic.BaseModel.model_validate_json()`. If parsing throws a `ValidationError`, the sample is invalid.

Functional verification gives you **mathematical certainty**. It turns synthetic data generation into a rejection sampling problem where only provably correct solutions survive.

### Tier 3: LLM-as-a-Judge (Rubric Scoring)
For creative writing, summarization, or general reasoning where no unit test exists, use a larger frontier model as an evaluator.

Do not ask the judge: *"Is this good? (1-10)"*. Broad numeric scores have high variance and suffer from position bias.

Instead, supply a **structured rubric** with explicit evaluation criteria:

```text
Evaluate the following Assistant response to the User prompt.

[User Prompt]: {prompt}
[Assistant Response]: {response}

Score each criterion from 0 to 2:
1. Instruction Following: Did it fulfill all constraints? (0 = missed, 1 = partial, 2 = complete)
2. Factual Accuracy: Are claims true and verifiable? (0 = hallucinated, 1 = questionable, 2 = fully accurate)
3. Directness: Is extraneous conversational fluff absent? (0 = heavy filler, 1 = mild filler, 2 = clean and direct)

Output your evaluation in strict JSON:
{"following": int, "accuracy": int, "directness": int, "total": int, "reason": "concise explanation"}
```

Only accept samples that achieve a perfect score of 6/6.

## The Mathematics of Model Collapse

What happens if an organization skips verification and simply trains Generation 1 on synthetic data, then trains Generation 2 on Generation 1's outputs, and repeats this for five cycles?

In 2023, Shumailov et al. published **The Curse of Recursion: Training on Generated Data Makes Models Forget** (arXiv:2305.17493, later published in *Nature* in 2024). They proved mathematically and empirically that recursive training on synthetic data leads inexorably to **model collapse**.

### The Mathematical Derivation
Let the true, underlying real-world data distribution be $p_0(x)$.

A machine learning model $M_1$ with parameters $\theta_1$ is trained on a finite sample $D_0 \sim p_0$ of size $M$:

$$
\theta_1 = \arg\max_\theta \sum_{x \in D_0} \log p_\theta(x)
$$

The resulting model defines an approximation distribution $p_1(x) = p_{\theta_1}(x)$.

Now, Generation 2 does not have access to $D_0$. It generates a synthetic dataset $D_1 \sim p_1$ of size $M$, and trains model $M_2$ with parameters $\theta_2$. In general, for generation $k+1$:

$$
D_k \sim p_k, \qquad \theta_{k+1} = \arg\max_\theta \sum_{x \in D_k} \log p_\theta(x)
$$

Consider what happens to the variance and the tails of the distribution.

Assume a simple one-dimensional Gaussian distribution $p_0(x) = \mathcal{N}(\mu_0, \sigma_0^2)$.

At each step, we draw $M$ discrete samples. The sample variance $s_k^2$ of $M$ samples drawn from a distribution with true variance $\sigma_k^2$ is an estimator:

$$
\mathbb{E}[s_k^2] = \frac{M - 1}{M} \sigma_k^2 = \left(1 - \frac{1}{M}\right) \sigma_k^2
$$

When model $k+1$ fits its parameters to this sample, its estimated variance $\sigma_{k+1}^2$ matches the sample variance:

$$
\mathbb{E}[\sigma_{k+1}^2] = \left(1 - \frac{1}{M}\right) \mathbb{E}[\sigma_k^2]
$$

Unrolling this recurrence across $k$ generations:

$$
\mathbb{E}[\sigma_k^2] = \sigma_0^2 \left(1 - \frac{1}{M}\right)^k
$$

Because $\left(1 - \frac{1}{M}\right) < 1$ for any finite sample size $M$, as the number of recursive generations $k \to \infty$:

$$
\lim_{k \to \infty} \mathbb{E}[\sigma_k^2] = 0
$$

<Callout type="math" title="Worked Numeric Example: Variance Erosion Across Generations">
  Suppose you train recursively using batches of $M = 1{,}000$ synthetic samples per generation.
  The shrinkage factor per generation is:
  $$
  1 - \frac{1}{M} = 1 - \frac{1}{1{,}000} = 0.999
  $$
  Over 500 recursive updates:
  $$
  \frac{\sigma_{500}^2}{\sigma_0^2} = (0.999)^{500} \approx 0.606
  $$
  The variance of the distribution has contracted by **39.4%**.

  Now consider what happens to the tails. Suppose an edge-case concept (such as a rare legal clause or a niche GPU assembly instruction) lives at $z = 3.0$ standard deviations from the mean in the original distribution $p_0$.
  In a standard normal distribution, the probability of sampling beyond ${}3\sigma$ is:
  $$
  P(X > 3\sigma_0) = 1 - \Phi(3.0) \approx 0.00135\ (0.135\%)
  $$
  In a sample of $M = 1{,}000$, the expected number of occurrences is ${}1{,}000 \times 0.00135 = 1.35$. There is a $P = (1 - 0.00135)^{1000} \approx 25.9\%$ probability that **zero** occurrences appear in the sample.

  Once a generation produces zero occurrences of that tail concept, it is completely absent from $D_k$. Model $M_{k+1}$ gives that concept near-zero probability. In subsequent generations, that concept can never be recovered. The tail is permanently erased.
</Callout>

### Early Collapse versus Late Collapse
Shumailov et al. categorized model collapse into two distinct chronological phases:

1. **Early Model Collapse**:
   - The model remains fluent and grammatically coherent.
   - However, it loses variance in the tails: rare facts, minority viewpoints, specialized vocabularies, and complex mathematical reasoning capabilities vanish.
   - The model begins to output bland, generic, homogenized text. When asked for creative writing, it reuses the same five plot structures.

2. **Late Model Collapse**:
   - The model loses ability to model the primary modes of the distribution.
   - Representations across layers degenerate.
   - The model begins emitting repetitive gibberish. In the famous example from the Shumailov paper, an LLM initialized on English Wikipedia text about medieval architecture degenerated by Generation 9 into:
     > *"architecture. In addition to the, when the, was the, of the, and the, was the... the tower of the church of the church of the church of..."*

## The Cure: How to Safely Train on Synthetic Data

Synthetic data is not inherently evil; **unfiltered recursive synthetic data** is evil. Modern frontier models (including Llama 3, Qwen 2.5, and DeepSeek) rely heavily on synthetic data. How do they avoid model collapse?

They follow three non-negotiable architectural rules:

### Rule 1: Always Maintain a Real Data Anchor
Never train a model on 100% synthetic data.

Always preserve a permanent, inviolable cache of high-quality human data. When creating your SFT or pretraining mixture, enforce an **anchor ratio**:

$$
D_{\text{train}} = \lambda D_{\text{human}} + (1 - \lambda) D_{\text{synthetic}}
$$

where $\lambda \in [0.20, 0.50]$.

By keeping 20% to 50% authentic human data in every single training run, you inject true distributional entropy and preserve the fat tails of human language that prevent variance collapse.

### Rule 2: Rejection Sampling via Functional Verification
Only include synthetic samples that have passed rigorous functional checks (Tier 2). If a model generates 100 solutions to a coding task, and only 8 pass all unit tests and static analysis, keep only those 8.

When you train only on verified successes, you are not performing naive recursive training ($D_k \sim p_k$). You are performing **reinforcement-guided filtering**, which shifts the distribution mode toward correctness rather than collapsing variance into error modes.

### Rule 3: Cross-Architecture Distillation
Do not train a model recursively on its own raw outputs. Distill from an entirely different model family or a vastly larger teacher (e.g. generating data with a 405B parameter teacher to train an 8B student). The larger teacher has different inductive biases, preventing the student from compounding its own idiosyncratic blind spots.

<Callout type="pitfall" title="The Perils of 'Self-Play' without Ground Truth">
  Self-play works in games like Chess and Go because the rules of the board and the win condition are mathematically absolute: you either checkmated the king or you did not.
  
  In natural language, there is no natural board boundary. If you allow an LLM to evaluate its own conversational outputs without a deterministic verifier, it will reward its own stylistic habits, accelerating model collapse. Ground truth is non-negotiable.
</Callout>

<KeyNotes>
  1. **The verification funnel**: Filter synthetic data in tiers: fast heuristics (length, regex, zlib compression), deterministic functional execution (unit tests, math solvers), and LLM-as-a-judge rubrics.
  2. **Zlib compression metric**: Repetitive token loops yield unnaturally low compression ratios ($C_{\text{ratio}} < 0.20$), while high-entropy character garbage yields $C_{\text{ratio}} > 0.85$.
  3. **Functional verification over human opinion**: A sandboxed Python unit test or SymPy algebraic proof provides mathematical certainty of correctness that human review cannot match at scale.
  4. **Model collapse mechanism**: Training models recursively on unverified synthetic outputs causes variance to shrink by $(1 - 1/M)$ per generation, erasing distribution tails.
  5. **Early vs late collapse**: Early collapse eliminates rare concepts, edge cases, and vocabulary; late collapse causes representations to fail completely into repetitive gibberish.
  6. **The human anchor rule**: Always anchor synthetic training sets with 20% to 50% authentic human data to preserve linguistic entropy and prevent mode collapse.
</KeyNotes>
